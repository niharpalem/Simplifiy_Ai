HPSv3: Human Preference Score v3

Evaluating Text-to-Image Models the Human Way

Paper: arxiv.org/pdf/2508.03789

1What is HPSv3?

HPSv3 is a trained rating system that predicts how much humans would like AI-generated images. Think of it as an AI judge that learned from 1.17 million human preference comparisons.

Component Description
HPSv3 Human Preference Score model - rates image quality
HPDv3 Dataset with 1.17M human preference comparisons
CoHP Chain of Human Preference - reasoning process for iterative improvement

2Problems with Current Evaluation Methods

👎Issue 1: Limited Data Distribution

Constraint Problem Impact
Data Distribution Limited style coverage, temporal bias, narrow demographics Poor generalization to new styles/domains
Model Design Fixed CLIP/BLIP backbones, single-score output Can't capture nuanced aesthetics
Training Schema Binary comparisons only, no uncertainty, coarse labels Misses preference magnitude and human disagreement

👎Issue 2: CLIP/BLIP Limitations

Why they fail at quality assessment:

  • Contrastive Training: Trained to match text-image pairs, not evaluate quality
  • Semantic Focus: Understands what is in the image, not how well it's rendered
  • Missing Details: Poor at capturing lighting, composition, artistic style
Example: CLIP sees "a dog" and "a poorly drawn dog" as similar because semantic content matches - it doesn't evaluate quality.

👎Issue 3: KL Divergence Problem

Scenario: 6 people prefer Image A, 4 prefer Image B

Human Reality: "People are split on this, preferences vary" What KL forces model to learn: "A is EXACTLY 60% better" Result: Model overfits to noisy labels instead of learning real patterns

Better Approach: Model should learn "A is slightly preferred, but it's close" with uncertainty.

3HPSv3 Solution

✅Their Approach

  • Well-curated Dataset: HPDv3 with diverse, high-quality annotations
  • Better Feature Encoder: QWen2-VL for multimodal understanding
  • Uncertainty-Aware Loss: Handles annotator disagreement naturally

5Model Architecture

Architecture Flow: (Image, Prompt) → QWen2-VL Encoder → MLP → (μ, σ)
Component Role
QWen2-VL Powerful vision-language encoder for feature extraction
MLP Multi-layer perceptron outputs μ (mean score) and σ (uncertainty)

6Uncertainty-Aware Training

Traditional Approach (Equation 2)

r1 = fϕ(Eθ(x1,c)) - single fixed score r2 = fϕ(Eθ(x2,c)) - single fixed score P(x1 > x2|c) = sigmoid(r1 - r2)
Characteristic Details
Output ONE number per image: r1, r2
Confidence Always equally confident in predictions
Problem Can't handle annotation disagreement or uncertainty

Example: r1=6.0, r2=5.0 → P(x1>x2) = 0.73 (always this confident)

Uncertainty-Aware Approach (Equation 3)

Model outputs: μ1, σ1 (for image 1) and μ2, σ2 (for image 2) r1 ~ N(μ1, σ1) - distribution of possible scores r2 ~ N(μ2, σ2) - distribution of possible scores P(x1 > x2|c) = ∫∫ sigmoid(r1-r2) × N(r1|μ1,σ1) × N(r2|μ2,σ2) dr1 dr2
Characteristic Details
Output TWO numbers per image: μ (mean) and σ (uncertainty)
Score Type Distribution, not fixed value
Confidence Large σ = low confidence; Small σ = high confidence
Calculation Integral considers ALL possible (r1, r2) combinations

Example: μ1=6.0, σ1=2.0 | μ2=5.0, σ2=2.0

  • Tries r1∈[2,10] and r2∈[1,9] in all combinations
  • Final P(x1>x2) ≈ 0.52 (less confident due to large σ)

Why This Works Better

Scenario Traditional Model Uncertainty-Aware Model
18/19 annotators agree r1=8.0, r2=3.0 (confident) μ1=8.0, σ1=0.3 (confident, narrow distribution)
10/19 annotators agree r1=6.0, r2=5.5 (still confident) μ1=6.0, σ1=2.0 (uncertain, wide distribution)

Key Insight: Large σ = "I'm not sure" = handles annotation disagreement naturally, doesn't overfit to noisy labels.

7Chain of Human Preference (CoHP)

Inspired by Chain-of-Thought reasoning, CoHP iteratively improves image quality using HPSv3 as a reward model.

Stage 1: Model-wise Preference

Goal: Select the best model for the given prompt

  1. Each model (m1, m2, ..., mM) generates N images for the prompt
  2. HPSv3 scores all images
  3. Calculate average score for each model: r̄i = (1/N) Σ ri,j
  4. Select golden model: m* = argmax(r̄i)

Stage 2: Sample-wise Preference

Goal: Iteratively refine images from the golden model

Each Round (N+1 to N+S):

  1. Generate B images (batch)
  2. HPSv3 scores each image
  3. Select winner: I*k = highest score
  4. Add noise to winner + use as input for next round

Why Add Noise?

  • Keeps good features from winner
  • Allows model to fix flaws and explore variations
  • Progressive improvement instead of starting from scratch

Final Selection:

I* = argmax(rn,k) across ALL rounds Pick the single best image from all S refinement rounds

Key Insight: Each round builds on the previous best result → iterative quality improvement

It's like saying: "This image is good, now make something similar but better"

8Key Takeaways

Component Innovation Benefit
HPDv3 Dataset 1.17M comparisons, real photos, diverse models, 90% agreement threshold High-quality, reliable training data
QWen2-VL Encoder Powerful vision-language model Better feature extraction than CLIP/BLIP
Uncertainty-Aware Loss Outputs μ and σ (Gaussian distribution) Handles annotation disagreement, prevents overfitting
CoHP Two-stage iterative refinement Selects best model + progressively improves quality

🎯Bottom Line

HPSv3 is a trained rating system that predicts human preferences for generated images. It uses better data, better architecture, and uncertainty modeling to evaluate image quality the way humans actually do - accounting for subjective preferences and disagreements.
