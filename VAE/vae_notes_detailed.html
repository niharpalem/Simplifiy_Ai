Variational Auto Encoders

A Complete Guide: From Intuition to Implementation

PHASE 1

The Big Picture: Why VAE?

Generative vs Discriminative AI

Discriminative Generative
Learns: P(y|x) — "Given input, what's the label?" Learns: P(x) — "What does the data look like?"
Example: CNN classifier Example: VAE, GAN, Diffusion
Can only classify Can generate NEW samples
Generative models learn the probability distribution of your data. Once learned, you can sample from this distribution to create entirely new, never-seen-before data.

The Goal

We want a model that can:

1. Compress images into a small "latent" representation

2. Generate new images by sampling random latent vectors

3. Interpolate smoothly between images in latent space

What is z (Latent Space)?

Think of z as a compressed representation of your image. A 784-pixel image gets compressed to just 20 numbers that capture its essential features.

Intuition: If you compress a "7" digit, z might encode: "has a horizontal stroke at top, diagonal stroke going down-left, no loops"

Training Objective

Simple: minimize reconstruction error

Loss = ||x - x̂||² = ||x - Decoder(Encoder(x))||²
The Problem: Regular autoencoders have a disorganized latent space. The encoder can place images anywhere in latent space — "7"s might be scattered all over, with huge gaps between them. If you sample a random z, you'll likely hit an empty region and generate garbage.
PHASE 3

VAE: Organizing the Latent Space

VAE forces the latent space to be organized by making the encoder output a probability distribution instead of a single point.

The Key Difference

❌ Regular Autoencoder

Encoder outputs: z = [0.5, -1.2, 0.8, ...]

A single fixed point in latent space

No organization enforced

✅ VAE

Encoder outputs: μ = [0.5, -1.2, ...] and σ = [0.1, 0.2, ...]

A distribution: z ~ N(μ, σ)

Forced to be close to N(0,1)

Input x
→
Encoder
→
μ, σ
→
Sample z
→
Decoder
→
Output x̂

Why Does This Help?

By forcing all distributions q(z|x) to stay close to N(0,1):

• Similar images cluster together (smooth latent space)

• No "holes" in latent space (every region decodes to something meaningful)

• Random sampling works! Sample z ~ N(0,1) → get valid images

PHASE 4

The Mathematics: Key Distributions

Distribution Meaning In VAE
P(z) — Prior What we believe z looks like before seeing any data We assume N(0, 1)
P(x|z) — Likelihood Probability of generating x given latent z Decoder models this
P(z|x) — Posterior Given image x, what z produced it? Intractable! We approximate it
q(z|x) — Approx. Posterior Our learnable approximation to P(z|x) Encoder outputs: N(μ, σ)
Why can't we compute P(z|x) directly?
By Bayes: P(z|x) = P(x|z)P(z) / P(x)

The problem is P(x) = ∫ P(x|z)P(z) dz requires integrating over ALL possible z values — computationally impossible for high dimensions.
Variational Inference: Instead of computing P(z|x), we learn an approximation q(z|x) that's easy to work with (a Gaussian). We train it to be as close as possible to the true P(z|x).
PHASE 5

The Loss Function (ELBO)

The Theoretical Form

ℒ = 𝔼q(z|x)[log p(x|z)] − KL(q(z|x) || p(z))
↑ Data Consistency                  ↑ Regularization

This is called the Evidence Lower Bound (ELBO). We maximize this.

The Practical Form (for optimization)

Since optimizers minimize, we flip the sign:

Loss = −𝔼[log p(x|z)] + KL(q(z|x) || p(z))
↑ Reconstruction Loss        ↑ KL Divergence Loss

What Each Term Does

Term Purpose Effect if too weak
Reconstruction
−log p(x|z)		 Forces decoder to accurately reconstruct input Blurry outputs, poor reconstruction
KL Divergence
KL(q||p)		 Forces encoder distribution close to N(0,1) Disorganized latent space, bad generation

Code Translation

Theory PyTorch Code
−log p(x|z)
Reconstruction		 F.mse_loss(x_reconstructed, x)
or F.binary_cross_entropy(x_reconstructed, x)
KL(q(z|x) || p(z))
Regularization		 -0.5 * torch.sum(1 + log_var - mu**2 - log_var.exp())
The KL divergence has a closed-form solution when both distributions are Gaussian! That's why we choose q(z|x) = N(μ, σ) and p(z) = N(0, 1).

KL Divergence Closed Form Derivation

For q(z|x) = N(μ, σ²) and p(z) = N(0, 1):

KL = −½ Σ (1 + log(σ²) − μ² − σ²)

In code, we output log_var = log(σ²) instead of σ directly for numerical stability:

# mu: [batch, latent_dim]
# log_var: [batch, latent_dim] (this is log(σ²))
kl_loss = -0.5 * torch.sum(1 + log_var - mu**2 - log_var.exp())

Common Misconception

KL Divergence is NOT comparing latent vs input!

❌ Wrong: "KL measures difference between z and x"
✅ Correct: "KL measures difference between q(z|x) and N(0,1)"

The KL loss compares the encoder's output distribution to a standard normal. This forces all encoded distributions to cluster around the origin.

Why KL Divergence Enables Generation

❌ Without KL Loss

Encoder maps freely:

"7"s → z = [50, -30, ...]

"3"s → z = [-80, 40, ...]

Random z ~ N(0,1) lands in empty space → garbage output

✅ With KL Loss

Encoder forced toward N(0,1):

"7"s → z near [0.5, -0.3, ...]

"3"s → z near [-0.2, 0.4, ...]

Random z ~ N(0,1) lands in meaningful region → realistic output

The Big Picture:
• Reconstruction loss teaches decoder what each z region should produce
• KL loss ensures all training data maps to regions we can easily sample from (near origin)
• Together: random samples from N(0,1) land where decoder knows what to do
PHASE 6

The Reparameterization Trick

The Backpropagation Problem:
We need to sample z ~ N(μ, σ), but sampling is not differentiable!
Gradients cannot flow through a random sampling operation.
Forward pass: x → Encoder → [μ, σ] → z = sample(μ, σ) → Decoder → x̂ → Loss ↑ STOP! Can't backprop through random sampling

The Core Problem

Direct sampling is a process, not an equation. "Pick a random number from this distribution" has no mathematical formula connecting μ to z.

Calculus only works on equations. No equation = no derivative = no training.

The Trick: Rewrite the random process as an equation!
z = μ + σ × ε     where     ε ~ N(0, 1)
Same random z, but now expressed as a clear mathematical relationship.

Math Example: Why This Works

Let's say encoder outputs: μ = 2, σ = 0.5

❌ Without Reparameterization

z = sample from N(μ=2, σ=0.5)
z = 2.3 (random value)

∂z/∂μ = ??? 
No formula connecting μ to z
Gradient undefined. Training stops.

✅ With Reparameterization

ε = 0.6 (sampled, now fixed)
z = μ + σ × ε
z = 2 + 0.5 × 0.6 = 2.3

∂z/∂μ = 1
∂z/∂σ = ε = 0.6
Clear gradients. Training works!

Same z value (2.3), but one version has a differentiable path back to μ and σ.

How Randomness Still Works

Within a single forward-backward pass:

1. Sample ε = 0.6 (random, but now FIXED for this pass) 2. Compute z = μ + σ × 0.6 (deterministic math) 3. Compute loss 4. Backprop: ∂z/∂μ = 1, ∂z/∂σ = 0.6 (clear gradients!) 5. Update μ, σ

For that one pass, ε is just a constant number. The randomness already happened — now it's frozen.

Next pass → new ε. Over many passes, you explore the full distribution. But each individual pass has clean, differentiable math.

The whole trick: We moved randomness from inside the operation to an input. The operation itself (μ + σ × ε) is now just addition and multiplication — fully differentiable.

Code Implementation

def reparameterize(self, mu, log_var):
    # log_var = log(σ²), so σ = exp(log_var / 2) = exp(log_var * 0.5)
    std = torch.exp(0.5 * log_var)
    
    # Sample ε ~ N(0, 1)
    eps = torch.randn_like(std)
    
    # z = μ + σ * ε
    z = mu + std * eps
    return z
Why log_var instead of σ?
• σ must be positive, but neural networks output any real number
• log(σ²) can be any real number → exp() converts it to positive σ
• More numerically stable during training
PHASE 7

Complete Example Walkthrough

🎯 Setup: MNIST Digit "7"

Input: 28×28 grayscale image = 784 pixels

Latent dimension: 20

Goal: Train VAE, then generate new "7"s

1 Forward Pass: Encoder

Input image x:

x.shape = [1, 784] (flattened 28×28)

Encoder architecture:

x [784] → Linear(784, 400) → ReLU → Linear(400, 20) → μ
                                      ↘ Linear(400, 20) → log_var

Encoder outputs:

μ = [0.8, -0.3, 1.2, 0.1, -0.9, ...] (20 values) log_var = [-1.2, -0.8, -1.5, -0.5, -1.0, ...] (20 values)

This means: "This '7' probably came from a Gaussian centered at μ with spread σ = exp(log_var/2)"

2 Reparameterization: Sample z

Sample random noise:

ε ~ N(0,1) = [0.5, -1.1, 0.2, 0.8, -0.3, ...] (20 values)

Compute z:

σ = exp(log_var * 0.5)
  = exp([-0.6, -0.4, -0.75, -0.25, -0.5, ...])
  = [0.55, 0.67, 0.47, 0.78, 0.61, ...]

z = μ + σ * ε
  = [0.8, -0.3, 1.2, ...] + [0.55, 0.67, 0.47, ...] * [0.5, -1.1, 0.2, ...]
  = [0.8 + 0.275, -0.3 - 0.737, 1.2 + 0.094, ...]
  = [1.075, -1.037, 1.294, ...]
z = [1.075, -1.037, 1.294, 0.724, -1.083, ...] (20 values)

3 Forward Pass: Decoder

Decoder architecture:

z [20] → Linear(20, 400) → ReLU → Linear(400, 784) → Sigmoid → x̂

Output:

x̂.shape = [1, 784] (reconstructed image, values 0-1)

This should look like the original "7"!

4 Compute Loss

Reconstruction Loss (Binary Cross Entropy):

L_recon = F.binary_cross_entropy(x̂, x, reduction='sum')
        = -Σ[x·log(x̂) + (1-x)·log(1-x̂)]
        = 152.3  # example value

KL Divergence Loss:

L_kl = -0.5 * Σ(1 + log_var - μ² - exp(log_var))
     = -0.5 * Σ(1 + [-1.2, -0.8, ...] - [0.64, 0.09, ...] - [0.30, 0.45, ...])
     = -0.5 * (-15.6)  # summed over all 20 dimensions
     = 7.8  # example value

Total Loss:

L_total = L_recon + L_kl = 152.3 + 7.8 = 160.1

5 Backpropagation

Gradient flow:

L_total ↓ L_recon ────────────────────────────────────┐ ↓ ↓ ∂L/∂x̂ x̂ ↓ ↑ Decoder weights ←──── ∂L/∂W_dec ←───────── z ↓ ↑ ↓ z = μ + σ*ε ↓ ↑ ↑ ↓ ∂z/∂μ=1 ∂z/∂σ=ε ↓ ↑ ↑ L_kl ─────────────────────────→ μ, log_var ↓ ↑ ∂L_kl/∂μ = μ │ ∂L_kl/∂log_var = 0.5*(exp(log_var) - 1) ↓ ↑ Encoder weights ←──── ∂L/∂W_enc ───┘

Key insight: Both losses contribute gradients to the encoder:

• L_recon pushes μ, σ to encode information needed for reconstruction

• L_kl pushes μ → 0 and σ → 1 (standard normal)

The encoder learns to balance these competing objectives!

6 Generation (After Training)

To generate new images, we don't need the encoder at all!

# Sample from standard normal (the prior we enforced)
z_random = torch.randn(1, 20)  # [1, 20]

# Decode to image
generated_image = decoder(z_random)  # [1, 784]

# Reshape to 28x28 and display
img = generated_image.view(28, 28)

Because KL divergence forced the latent space to be N(0,1), random samples decode to meaningful images!

Summary: The Complete Picture

┌─────────────────────────────────────────────────────────────────────┐ │ TRAINING │ │ │ │ x ──→ [Encoder] ──→ μ, σ ──→ z=μ+σε ──→ [Decoder] ──→ x̂ │ │ │ │ │ │ ↓ ↓ │ │ KL Loss Reconstruction Loss │ │ (push toward N(0,1)) (make x̂ match x) │ │ │ │ │ │ └────────┬───────────────┘ │ │ ↓ │ │ Total Loss │ │ ↓ │ │ Backpropagate │ └─────────────────────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────────────────────┐ │ GENERATION │ │ │ │ z ~ N(0,1) ──→ [Decoder] ──→ New Image! │ │ │ │ (No encoder needed - just sample and decode) │ └─────────────────────────────────────────────────────────────────────┘

Key Takeaways

Concept Why It Matters
Encoder outputs μ, σ Represents uncertainty, not just a point estimate
KL Divergence loss Forces q(z|x) toward N(0,1) → organizes latent space for generation
Reparameterization trick Rewrites sampling as equation (z = μ + σε) → enables backprop
log_var instead of σ Numerical stability (σ must be positive)
N(0,1) prior Simple to sample from during generation

The Two-Phase Mental Model

Training Phase:
Image → Encoder → z (forced near N(0,1) by KL) → Decoder → Reconstruct

Encoder teaches decoder: "this region of N(0,1) should decode to faces", "this region to cats", etc.
Generation Phase:
Random z ~ N(0,1) → Decoder → New image

No encoder needed! Encoder's job was just to organize the latent space during training. For generation, we only need the decoder.
